# MEZA — пилот «Склад» на твоей машине (Mac, Apple Silicon M4, 24GB)

Все команды ниже выполняются у тебя локально, не в этой облачной сессии — здесь только
подготовлены файлы.

## 1. Модель

```bash
ollama pull qwen2.5:7b-instruct
cd sklad
ollama create meza-sklad -f Modelfile.sklad
ollama run meza-sklad
```

Проверь вручную в терминале: "Найди болт М8х40" — модель должна ответить в своём стиле
(но без реальных данных — инструменты из Modelfile подключаются только через Open WebUI,
см. шаг 3). Если ответ выглядит нормально по тону и формату — переходи дальше.

Если `qwen2.5:7b-instruct` не подтянется под этим тегом, возьми `qwen2.5:7b` — в библиотеке
Ollama это тот же инструкционный чекпоинт.

## 2. Open WebUI (веб-чат)

Самый простой вариант на Mac — через `pip` (без Docker Desktop):

```bash
python3 -m venv ~/.meza-webui
source ~/.meza-webui/bin/activate
pip install open-webui
open-webui serve
```

Открой http://localhost:8080 — Open WebUI сам найдёт локальный Ollama на
`http://127.0.0.1:11434`. Создай учётку (локально, без облака) и зайди.

## 3. Подключение инструментов склада

1. В Open WebUI: **Workspace → Tools → + Create new tool**.
2. Скопируй туда содержимое `sklad/tools/warehouse_tools.py` целиком.
3. Сохрани (имя тула, например, `warehouse`).
4. **Workspace → Models → meza-sklad → Edit** → включи галку у инструмента `warehouse`
   в разделе Tools. Сохрани.

Теперь модель сама решает, когда вызвать `find_item`, `check_stock`, `list_low_stock`
или `build_route`, и получает реальные данные вместо выдумывания.

## 4. Проверка на тестовых сценариях

В чате с `meza-sklad` (с включённым тулом) спроси по очереди:
- «Где лежит Автомат 16А и сколько его осталось?» → должен вызвать `check_stock`,
  предупредить про низкий остаток (12 < 20).
- «Собери маршрут для заказа ORD-500» → должен вызвать `build_route`, выдать
  пронумерованный маршрут по зонам A → B → D.
- «Какие товары заканчиваются?» → должен вызвать `list_low_stock`.
- «Найди гайку» → `find_item`, несколько совпадений обработать корректно.

Если модель отвечает без вызова тула (выдумывает) — проверь, что галка тула включена
именно у модели `meza-sklad`, и что qwen2.5:7b-instruct поддерживает function calling
(поддерживает из коробки в Ollama ≥ 0.3).

## 5. Переход с mock-данных на реальный склад

Сейчас `sklad/data/warehouse_mock.json` — тестовые данные. Чтобы подключить настоящий
склад, замени источник в `sklad/tools/warehouse_tools.py` (функция `_load_data`) на
реальный: выгрузка из 1С/WMS, SQL-запрос или вызов внутреннего API. Структура (sku, name,
zone, aisle, shelf, qty, low_stock_threshold) может остаться той же, если реальный источник
отдаёт эти поля — тогда меняется только `_load_data`, остальной код не трогаем.

## 6. Автозапуск (когда пилот подтверждён)

Когда убедишься, что всё работает стабильно — оборачиваем `ollama serve` и
`open-webui serve` в `launchd`-юниты, чтобы поднимались при старте системы. Делаем на
следующем этапе, после теста на реальных данных.
